# 生产日志与审计日志运行手册

本项目的应用日志是单行 JSON，同时写入 stdout/stderr 和应用日志文件。PM2/systemd 仍可采集标准输出；文件写入失败会被忽略，不会阻断首页、礼品站、Ops 或后台任务。

## 日志位置与格式

- 默认文件：`/var/log/unionam/unionam-homepage/application.jsonl`
- 可选覆盖：`UNIONAM_APPLICATION_LOG_PATH`，必须是绝对路径
- 稳定服务名：`unionam-homepage`
- 组件：`homepage`、`gift`、`gift-ops`、`background`
- 必备字段：`time`、`level`、`service`、`environment`、`event`、`result`、`request_id`、`duration_ms`、`error_code`
- 每个进入 Next.js 的动态请求由应用生成新的 UUID，请求头中的公网 `X-Request-ID` 不会被信任；响应统一返回 `X-Request-ID`。

生产主机需要预先创建目录，并授予运行 Next.js 的账号写权限：

```bash
sudo install -d -m 0750 -o unionam -g unionam /var/log/unionam/unionam-homepage
sudo install -m 0640 -o unionam -g unionam /dev/null /var/log/unionam/unionam-homepage/application.jsonl
```

不要把 Authorization、Cookie、Token、密码、验证码、AccessKey、请求正文、上传模型/图片内容、文件名、签名 URL 或环境变量放入日志参数。统一脱敏器会递归过滤 `password`、`passwd`、`pwd`、`token`、`authorization`、`cookie`、`secret`、`phone`、`mobile`、`email`、`access_key`、`signature`、会话/CSRF/验证码字段，以及 body、prompt、image、filename、object_key、环境变量类字段；字符串中的凭据、邮箱、手机号、带查询串 URL 也会屏蔽。CR/LF 和控制字符会被转义，字符串限 1000 字符，数组、对象键数和递归深度均有限制。

## 当前事件清单

- HTTP：`http.request.accepted`
- 安全与登录：`security.access_denied`、`auth.wecom_login.succeeded`、`auth.wecom_login.failed`
- 员工与配置：`audit.employee_application.submitted`、`audit.employee_approval.changed`、`audit.quote_settings.updated`
- 礼品申请：`audit.print_request.created`、`audit.print_request.submitted`、`audit.print_request.updated`、`audit.print_request.cancelled`
- 后台 AI：`task.ai.created`、`task.ai.started`、`task.ai.completed`、`task.ai.failed`、`task.ai.cancelled`
- AI 供应商尝试：`task.ai_provider_attempt.started`、`task.ai_provider_attempt.completed`、`task.ai_provider_attempt.failed`
- 企微通知：`task.wecom_notification.created`、`task.wecom_notification.started`、`task.wecom_notification.completed`、`task.wecom_notification.failed`
- OSS：既有 `audit.model_asset_uploaded`、`audit.request_attachment_uploaded`、`audit.gift_draft_deleted`、`audit.model_asset_deleted`，以及 `audit.oss_asset.read`
- 既有 `gift_ops_audit_events` 数据库审计保留；通过统一入口写入的事件会同步写应用 JSON。部分事务内原生 SQL 审计点也有对应 JSON 事件。

项目目前没有服务端业务数据 CSV/Excel 导出接口，因此没有虚构 `data_export` 事件。浏览器本地生成 STL 属于客户端行为，不含服务端业务数据导出审计点；后续若新增服务端导出，必须在成功、拒绝和失败处补事件，且不得记录导出内容或文件名。

## 上线前验收（仅命令，不在本次改造中执行部署）

```bash
npm run typecheck -w apps/homepage
npm run test:logging -w apps/homepage
npm run test:navigation -w apps/homepage
npm run test:privacy-consent -w apps/homepage
npm run build -w apps/homepage
```

上线后抽查：

```bash
curl -sS -D - https://unionam.com/api/health -o /dev/null | grep -i '^x-request-id:'
sudo tail -n 20 /var/log/unionam/unionam-homepage/application.jsonl | jq -c .
sudo jq -r 'select(.event == "security.access_denied") | [.time,.request_id,.error_code] | @tsv' /var/log/unionam/unionam-homepage/application.jsonl | tail
pm2 logs 3dp-homepage-blue --lines 20 --nostream
pm2 logs 3dp-homepage-green --lines 20 --nostream
```

现有发布入口保持不变：

```bash
git push origin main
./scripts/deploy/production.sh
```

## 回滚

应用代码沿用现有蓝绿回滚：从 `/srv/unionam/deploy/homepage-deployments.log` 查前一版本端口，健康检查成功后，原子写入 `/srv/unionam/deploy/homepage-active-port`。本次没有数据库迁移；回滚代码即可。不要删除日志文件，避免审计链断裂。

```bash
curl -fsS http://127.0.0.1:<previous-port>/api/health
printf '%s\n' '<previous-port>' | sudo tee /srv/unionam/deploy/homepage-active-port
curl -fsS https://unionam.com/api/health
```

## SLS / LoongCollector 人工项

本次不修改 SLS、OSS、Nginx 或线上采集器。管理员需要在 LoongCollector 中人工新增或核对文件采集路径：

```text
/var/log/unionam/unionam-homepage/application.jsonl
```

采集配置应使用 JSON 模式、UTF-8、每行一个事件，以 `time` 作为时间字段，并为 `service`、`environment`、`component`、`event`、`result`、`request_id`、`error_code` 建索引；设置保留期和访问权限，避免普通业务账号读取。PM2 stdout/stderr 可以继续作为应急来源，但若同时采集文件和 stdout，要在 SLS 侧按 `request_id + event + time` 处理重复。上线后需人工验证采集延迟、JSON 解析失败率、权限拒绝告警、AI/通知失败告警与日志目录磁盘轮转策略。
